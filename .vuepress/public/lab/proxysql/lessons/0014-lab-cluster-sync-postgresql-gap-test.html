Lesson 0014 · Lab thực hành — kiểm chứng giả thuyết

Lab: gap pgsql_replication_hostgroups trong ProxySQL Cluster — thật hay không?

~15 phút. Lesson 13 nêu nghi ngờ: release note 3.0.8 không nêu tên pgsql_replication_hostgroups trong danh sách bảng được ProxySQL Cluster Sync. Tôi đã dựng lab thật với 2 node ProxySQL Cluster để kiểm chứng. Kết quả: nghi ngờ đó sai — bảng này đồng bộ tốt. Đây là ví dụ thật về lý do phải tự lab-test trước khi tin 100% vào tài liệu, kể cả tài liệu chính thức.

Thiết kế lab

2 node ProxySQL (proxysql1, proxysql2) join nhau thành 1 ProxySQL Cluster + 1 PostgreSQL primary/replica. Cấu hình pgsql_servers, pgsql_replication_hostgroups, pgsql_query_rules chỉ trên proxysql1, rồi quan sát proxysql2 có tự nhận được không — không đụng gì vào proxysql2 cả.

cd lab/0012-proxysql-cluster-postgresql-gap
docker compose up -d
sleep 25

# Join cluster hai chiều (mỗi node khai peer của nhau qua proxysql_servers, port = admin MySQL 6032)
# proxysql1: INSERT INTO proxysql_servers (hostname,port) VALUES ('proxysql2',6032); LOAD/SAVE PROXYSQL SERVERS
# proxysql2: INSERT INTO proxysql_servers (hostname,port) VALUES ('proxysql1',6032); LOAD/SAVE PROXYSQL SERVERS

Chi tiết dễ quênProxySQL Cluster giao tiếp qua admin port MySQL protocol (6032), không phải port PostgreSQL (6132) — dù mục tiêu là đồng bộ config PostgreSQL. Cluster sync luôn chạy trên kênh MySQL protocol, bất kể backend engine nào đang được đồng bộ.

Bước kiểm chứng: cấu hình chỉ trên proxysql1

-- Chỉ chạy trên proxysql1
INSERT INTO pgsql_servers (hostgroup_id,hostname,port) VALUES (0,'postgres-primary',5432);
INSERT INTO pgsql_servers (hostgroup_id,hostname,port) VALUES (1,'postgres-replica',5432);
INSERT INTO pgsql_replication_hostgroups (writer_hostgroup,reader_hostgroup,check_type)
  VALUES (0,1,'read_only');
LOAD PGSQL SERVERS TO RUNTIME; SAVE PGSQL SERVERS TO DISK;

Kết quả thật — proxysql2 (không đụng gì) sau vài giây

-- Trên proxysql2, KHÔNG chạy lệnh gì, chỉ SELECT:
SELECT * FROM pgsql_servers;             -- CÓ 2 dòng, giống proxysql1
SELECT * FROM runtime_pgsql_servers;     -- CÓ 2 dòng, giống proxysql1
SELECT * FROM pgsql_replication_hostgroups;  -- 0|1|read_only|pg-repl  ← ĐÃ ĐỒNG BỘ

Log lỗi của proxysql2 xác nhận chính xác cơ chế:

[INFO] Cluster: detected a new checksum for pgsql_servers_v2 from peer proxysql1:6032 ...
[INFO] Cluster: Fetching PostgreSQL Servers v2 from peer proxysql1:6032 completed.
[INFO] Cluster: Fetching PostgreSQL Replication Hostgroups from peer proxysql1:6032 completed.
[INFO] Cluster: Fetching PostgreSQL Hostgroup Attributes from peer proxysql1:6032 completed.
[INFO] Cluster: Fetching PostgreSQL Servers SSL Params from peer proxysql1:6032 completed.

Kết luận đã kiểm chứngpgsql_replication_hostgroups được đồng bộ qua ProxySQL Cluster (kiểm chứng trên ProxySQL 3.0.10), cùng lúc với pgsql_servers_v2, pgsql_hostgroup_attributes, pgsql_servers_ssl_params. Release note 3.0.8 chỉ đơn giản không liệt kê đầy đủ — không có nghĩa là bảng đó bị bỏ ngoài cluster sync. Bài học: tài liệu chính thức có thể thiếu chi tiết dù không sai về hướng chính; log thật + lab thật vẫn là nguồn đáng tin nhất khi cần chắc chắn 100%.

Test thêm: query rule cũng đồng bộ live

-- Trên proxysql1, thêm 1 query rule mới, KHÔNG đụng proxysql2
INSERT INTO pgsql_query_rules (rule_id,active,match_digest,destination_hostgroup,apply)
  VALUES (10,1,'^SELECT',1,1);
LOAD PGSQL QUERY RULES TO RUNTIME; SAVE PGSQL QUERY RULES TO DISK;

-- 5 giây sau, trên proxysql2:
SELECT rule_id,match_digest,destination_hostgroup,apply FROM pgsql_query_rules;
-- 10|^SELECT|1|1   ← đồng bộ đúng, không cần chạm proxysql2

Trong lab này, sau khi cấu hình pgsql_replication_hostgroups chỉ trên proxysql1, proxysql2 có bảng đó không?

  • Không, phải cấu hình tay trên proxysql2
  • Có, đồng bộ tự động qua Cluster
  • Có nhưng chỉ sau khi restart proxysql2
  • Có nhưng chỉ đồng bộ pgsql_servers, không đồng bộ hostgroups

Một gotcha thật khác tìm thấy trong lúc lab (không liên quan gap ban đầu)

Khi 2 node cùng join proxysql_servers vào nhau ở cùng giây, log xuất hiện:

[ERROR] Cluster: detected a peer proxysql1:6032 with proxysql_servers version 2, epoch 1787026031 ...
Own version: 2, epoch: 1787026031, checksum ... Sync conflict, epoch times are EQUAL,
can't determine which server holds the latest config, we won't sync.

Gotcha thậtNếu 2 node ProxySQL Cluster được cấu hình proxysql_servers (danh sách peer) ở đúng cùng 1 giây (epoch giống nhau), ProxySQL không tự quyết được ai đúng và dừng đồng bộ bảng đó — thông báo lỗi lặp lại mỗi 30 lần kiểm tra. Cách khắc phục theo đúng thông báo: chạy lại LOAD PROXYSQL SERVERS TO RUNTIME trên node bạn muốn làm "nguồn sự thật" để tạo epoch mới, phá vỡ tie. Không ảnh hưởng tới việc đồng bộ pgsql_* — chỉ ảnh hưởng riêng bảng proxysql_servers (danh sách peer) trong lab này.

Điều còn chưa kiểm chứng — nếu muốn đào tiếp

stats_proxysql_servers_checksums — bảng bạn hay dùng để giám sát tình trạng đồng bộ cluster (xem Reference 0004) — không hiện bất kỳ dòng pgsql_* nào trong lab này, dù việc đồng bộ pgsql thực sự diễn ra (xác nhận qua log + dữ liệu). Đây là gap quan sát được thật: nếu bạn dựa vào bảng này để dashboard giám sát sức khoẻ Cluster, bạn sẽ không thấy tình trạng đồng bộ PostgreSQL — phải đọc error log hoặc tự diff bảng giữa các node.

Lesson 0010

ProxySQL cho PostgreSQL

~12 phút đọc + quiz. Mission của bạn vừa mở rộng: hệ thống thật có cả MySQL và PostgreSQL. Tin tốt — bạn không học lại từ đầu. Tin cần cẩn trọng — module này rất mới, có vài điểm "còn non" phải biết trước khi đưa vào production.

Mọi khái niệm bạn đã học vẫn đúng — chỉ đổi tên bảng

ProxySQL thêm hỗ trợ PostgreSQL từ bản 3.0 (tháng 9/2024), dùng lại đúng kiến trúc multi-layer config, multiplexing, monitor module, query rules, hostgroups mà bạn đã học ở Lesson 1-9 cho MySQL — chỉ đổi tiền tố bảng từ mysql_ sang pgsql_, và đổi port:

MySQL (đã học)PostgreSQL
mysql_servers / mysql_users / mysql_query_rulespgsql_servers / pgsql_users / pgsql_query_rules
mysql_replication_hostgroups (Lesson 2)pgsql_replication_hostgroups
Admin 6032, data 6033, client mysqlAdmin 6132, data 6133, client psql

Setup — song song đúng 4 bước của Lesson 3

-- 1. Thêm backend
INSERT INTO pgsql_servers (hostgroup_id, hostname, port) VALUES (0, '10.0.0.1', 5432);
LOAD PGSQL SERVERS TO RUNTIME; SAVE PGSQL SERVERS TO DISK;

-- 2. Monitor user (tạo trên PostgreSQL trước, xem gotcha dưới)
UPDATE global_variables SET variable_value='monitor' WHERE variable_name='pgsql-monitor_username';
UPDATE global_variables SET variable_value='monitor' WHERE variable_name='pgsql-monitor_password';
LOAD PGSQL VARIABLES TO RUNTIME; SAVE PGSQL VARIABLES TO DISK;

-- 3. App user
INSERT INTO pgsql_users (username, password, default_hostgroup) VALUES ('appuser','apppass',0);
LOAD PGSQL USERS TO RUNTIME; SAVE PGSQL USERS TO DISK;

-- 4. Connect thử qua ProxySQL
psql -h 127.0.0.1 -p6133 -U appuser -d mydatabase

Gotcha khác MySQLProxySQL chưa cho đặt database riêng cho monitor user — phải tạo 1 database riêng trên PostgreSQL cho user này (ví dụ proxymon), không dùng chung app database. Tài liệu chính thức ghi rõ đây là hạn chế tạm thời, "likely to change in the near future".

Read/write split tự động — vẫn dùng pg_is_in_recovery()

Giống hệt tư duy mysql_replication_hostgroups ở Lesson 2: khai báo writer/reader hostgroup, ProxySQL tự kiểm tra role của từng server (qua pg_is_in_recovery() thay vì read_only của MySQL) và tự chuyển server sang hostgroup đúng khi role đổi — kể cả khi PostgreSQL failover/promote một replica lên primary.

INSERT INTO pgsql_replication_hostgroups (writer_hostgroup, reader_hostgroup, check_type)
  VALUES (0, 1, 'read_only');
LOAD PGSQL SERVERS TO RUNTIME;

3 điểm "còn non" — đọc kỹ trước khi quyết định production

Vì mission của bạn là mission-critical, đây là phần quan trọng nhất của lesson này — không phải để dọa bạn, mà để bạn quyết định đúng version tối thiểu cần dùng:

Vấn đềVì sao quan trọng
Module chỉ mới từ 09/2024So với MySQL module đã production-hardened từ ~2013, PostgreSQL module còn rất trẻ — ít case thực tế đã kiểm chứng hơn nhiều
Extended Query Protocol chỉ hỗ trợ từ 3.0.4Driver PostgreSQL hiện đại (libpq, psycopg2, JDBC) mặc định dùng Extended Query Protocol (Parse/Bind/Execute nhiều bước) để chạy prepared statement. Bản ProxySQL trước 3.0.4 chỉ hiểu Simple Query — nghĩa là driver mặc định của bạn có thể không tương thích nếu dùng bản cũ hơn.
ProxySQL Cluster Sync cho PostgreSQL chỉ từ 3.0.8Nếu bạn định dùng ProxySQL Cluster (Lesson 4) để đồng bộ config giữa nhiều node cho cả 2 engine, node PostgreSQL cần bản ≥3.0.8 để config tự đồng bộ — bản cũ hơn không tự sync phần pgsql_*.

Việc cần làm ngayTrước khi thiết kế sâu hơn cho PostgreSQL, kiểm tra SELECT @@version; trên ProxySQL bạn định dùng — đảm bảo ≥ 3.0.8 để có đủ cả Extended Query Protocol và Cluster Sync. Đừng giả định "ProxySQL support Postgres" nghĩa là mọi feature đều sẵn sàng như module MySQL.

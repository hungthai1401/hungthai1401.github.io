Kiến trúc ProxySQL

Bản nén các khái niệm lõi. Dùng để tra cứu nhanh khi cấu hình, không phải để đọc tuyến tính.

Threading model

MySQL Worker Threads — xử lý phần lớn traffic client: auth, parse query, relay kết quả.

Admin Thread — cổng quản trị, port 6032 (protocol MySQL) và 6132 (protocol PgSQL).

Monitor Threads — ping backend liên tục, kiểm tra kết nối, đo replication lag.

Cluster Threads — đồng bộ config giữa các node ProxySQL (chỉ khi dùng ProxySQL Cluster).

Core components

Hostgroups Manager — nhóm các backend MySQL theo vai trò (writer/reader...). Mỗi hostgroup giữ pool connection riêng, có multiplexing (nhiều session frontend dùng chung ít connection backend) và tự route theo trạng thái read_only.

Query Processor — "bộ não": với mỗi query quyết định route đi đâu, có rewrite không, có cache không, có block không.

Query Digest — fingerprint hoá query (bỏ giá trị cụ thể) để match rule và thống kê hiệu quả.

Data flow (một query)

Client → Worker Thread → Query Processor (match rule, check cache)
       → Hostgroups Manager (lấy connection đúng hostgroup)
       → Backend MySQL → trả kết quả ngược lại Client

Vì sao "maximum uptime"

  • Đổi config qua Admin interface áp dụng runtime, không cần restart.
  • Config lưu trong SQLite nội bộ, tách disk (persist) và runtime (đang chạy) — có thể test trước khi LOAD ... TO RUNTIME.
  • "Angel process" tự giám sát và restart ProxySQL nếu crash.
  • Hỗ trợ cascade: App → P1 → {P2,P3,P4} → {B1,B2,B3} — nhiều tầng proxy chịu lỗi cho nhau.

ProxySQL Cluster (HA cho chính tầng proxy)

Khái niệmÝ nghĩa
Core nodeGiữ "Source of Truth", được liệt kê tường minh trong proxysql_servers của nhau, tự propagate thay đổi.
Satellite nodeChỉ pull config từ Core node, không propagate.
Cơ chế syncPull-based, kích hoạt khi lệch checksum. Có grace period (diffs_before_sync) để tránh sync do mất mạng tạm thời.
Được đồng bộGlobal variables, MySQL servers/hostgroups, MySQL users, query rules, danh sách proxysql_servers.
Theo dõi clusterstats_proxysql_servers_checksums, stats_proxysql_servers_metrics, runtime_checksums_values.

Lưu ý HAProxySQL Cluster đồng bộ config giữa các node ProxySQL — nó không tự cấp một VIP cho client kết nối vào. Muốn client luôn trỏ vào node ProxySQL còn sống, vẫn cần thêm cơ chế failover ở tầng network (Keepalived + VIP, load balancer, hoặc DNS-based) phía trước cluster.

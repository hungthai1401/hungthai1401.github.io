Lab Keepalived/VRRP bằng Docker — giới hạn cần biết

Đọc trước khi chạyLab này mô phỏng, không phải bản sao chính xác của production. Ba giới hạn cụ thể của Docker khiến cách lab khác với cách bạn sẽ làm trên VM/bare-metal thật.

3 giới hạn của Docker và cách lab lách qua

Giới hạnVì saoCách lab xử lý
Keepalived cần chung host với ProxySQL để VIP "gắn" vào đúng network interface mà ProxySQL đang lắng ngheTrên production, Keepalived và ProxySQL là 2 process trên cùng một máy, chia sẻ network stack tự nhiênDùng network_mode: "service:proxysqlN" cho container keepalived — 2 container chia sẻ network namespace, coi như "cùng một máy ảo nhỏ"

2 lỗi thực tế đã gặp khi chạy lab này

  1. Sai đường dẫn config. Image osixia/keepalived:2.0.20 không đọc /etc/keepalived/keepalived.conf — nó chạy keepalived với -f /usr/local/etc/keepalived/keepalived.conf (symlink tới file tự sinh từ template mặc định). Phải mount file config vào đúng /usr/local/etc/keepalived/keepalived.conf thì mới có hiệu lực. File trong lab đã được sửa đúng đường dẫn này.
  2. Fail-back cần restart cả sidecar keepalived, không chỉ ProxySQL. Vì keepalived1 dùng network_mode: "service:proxysql1", khi proxysql1 chết, network namespace nó tạo ra biến mất theo. Khi bạn docker start lab5-proxysql1 lại, container đó được cấp netns mới — nhưng keepalived1 (đã đang "Up" từ trước) vẫn còn giữ tham chiếu tới netns cũ đã chết, không tự nhận ra netns mới. Phải docker restart lab5-keepalived1 tường minh sau khi proxysql1 sống lại, để nó join lại đúng netns mới.

Sơ đồ network của lab

172.28.0.10  mysql-backend
172.28.0.11  proxysql1  <--netns chung--> keepalived1 (priority 150, MASTER)
172.28.0.12  proxysql2  <--netns chung--> keepalived2 (priority 100, BACKUP)
172.28.0.13  proxysql3  <--netns chung--> keepalived3 (priority 50,  BACKUP)
172.28.0.20  client (dùng để test, docker exec vào đây)
172.28.0.100 VIP — gắn vào node có priority cao nhất còn "sống" (port 6033 mở)

Lệnh vận hành lab

cd lab/0005-keepalived-vip
docker compose up -d

# Xem VIP đang ở node nào (chỉ 1 trong 3 có dòng 172.28.0.100)
docker exec lab5-keepalived1 ip addr show eth0 | grep 172.28.0.100
docker exec lab5-keepalived2 ip addr show eth0 | grep 172.28.0.100
docker exec lab5-keepalived3 ip addr show eth0 | grep 172.28.0.100

# Test traffic qua VIP (chạy từ container client, KHÔNG chạy trực tiếp từ Mac)
docker exec -it lab5-client mysql -h 172.28.0.100 -P 6033 -uappuser -papppass -e "SELECT 1"

# Gây failover: dừng node đang giữ VIP
docker stop lab5-proxysql1

# Chờ vài giây, kiểm tra lại — VIP phải chuyển sang proxysql2
docker exec lab5-keepalived2 ip addr show eth0 | grep 172.28.0.100
docker exec -it lab5-client mysql -h 172.28.0.100 -P 6033 -uappuser -papppass -e "SELECT 1"

# Fail-back: bật lại node ưu tiên cao nhất, RỒI restart luôn sidecar keepalived của nó
docker start lab5-proxysql1
docker restart lab5-keepalived1   # bắt buộc — netns cũ của keepalived1 đã chết theo proxysql1
# VIP sẽ tự chuyển về lab5-proxysql1 sau vài giây (priority 150 > 100)

Dọn lab

docker compose down -v

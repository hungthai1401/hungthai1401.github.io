ProxySQL cho PostgreSQL

Đổi tên bảng — mọi thứ đã học cho MySQL, đổi tiền tố

Tin tốtKiến trúc tổng (multi-layer config, multiplexing, monitor module, query rules, hostgroups, ProxySQL Cluster) là chung giữa 2 module — mọi khái niệm Lesson 1-9 học cho MySQL áp dụng gần như 1:1 về mặt tư duy cho PostgreSQL, chỉ đổi tên bảng/port.

Setup cơ bản (song song 4 bước của Lesson 3)

-- 1. Thêm backend
INSERT INTO pgsql_servers (hostgroup_id, hostname, port) VALUES (0, '10.0.0.1', 5432);
LOAD PGSQL SERVERS TO RUNTIME; SAVE PGSQL SERVERS TO DISK;

-- 2. Cấu hình monitor user (tạo user riêng trên PostgreSQL trước)
UPDATE global_variables SET variable_value='monitor' WHERE variable_name='pgsql-monitor_username';
UPDATE global_variables SET variable_value='monitor' WHERE variable_name='pgsql-monitor_password';
LOAD PGSQL VARIABLES TO RUNTIME; SAVE PGSQL VARIABLES TO DISK;

-- 3. Thêm app user
INSERT INTO pgsql_users (username, password, default_hostgroup) VALUES ('appuser','apppass',0);
LOAD PGSQL USERS TO RUNTIME; SAVE PGSQL USERS TO DISK;

-- 4. (tuỳ chọn) query rule
INSERT INTO pgsql_query_rules (rule_id,active,match_digest,destination_hostgroup,apply)
  VALUES (10,1,'^SELECT .*',1,1);
LOAD PGSQL QUERY RULES TO RUNTIME; SAVE PGSQL QUERY RULES TO DISK;

GotchaProxySQL chưa cho đặt database riêng cho monitor user (tính tới thời điểm viết) — phải tạo 1 database riêng cho user monitor trên PostgreSQL (ví dụ database proxymon), không dùng chung với app database.

Read/write split tự động — pgsql_replication_hostgroups

Giống mysql_replication_hostgroups: khai báo writer_hostgroup/reader_hostgroup, ProxySQL tự kiểm tra pg_is_in_recovery() mỗi server và tự chuyển server giữa 2 hostgroup khi role đổi (failover, promote).

INSERT INTO pgsql_replication_hostgroups (writer_hostgroup, reader_hostgroup, check_type)
  VALUES (0, 1, 'read_only');
LOAD PGSQL SERVERS TO RUNTIME;

pgsql-monitor_writer_is_also_reader (default true) — writer có tự nhận cả traffic đọc không, giống hành vi bạn đã học ở Lesson 2 cho MySQL. Đã kiểm chứng thật ở Lesson 12:

Giá trịKhi node được promote (read_only 1→0)
true (default)Copy vào writer hostgroup, vẫn ở lại reader hostgroup
falseChuyển hẳn vào writer hostgroup, gỡ khỏi reader hostgroup

ProxySQL Cluster Sync cho PostgreSQL (từ 3.0.8) — bảng nào được đồng bộ

Theo release note chính thức 3.0.8, cluster sync cho PostgreSQL cover đúng các bảng:

  • pgsql_query_rules
  • pgsql_servers (cả runtime và v2 layout)
  • pgsql_users
  • pgsql_variables
  • pgsql_servers_ssl_params (bảng mới, TLS per-backend)

Đã kiểm chứng thật (Lesson 14)Release note không nêu tên pgsql_replication_hostgroups, nhưng lab thật với 2 node Cluster (ProxySQL 3.0.10) xác nhận bảng này được đồng bộ — cùng với pgsql_hostgroup_attributes và pgsql_servers_ssl_params. Log peer thấy rõ: Fetching PostgreSQL Replication Hostgroups from peer ... completed. Release note chỉ thiếu chi tiết, không sai về việc có đồng bộ hay không. Lưu ý riêng: stats_proxysql_servers_checksums không hiện dòng nào cho bảng pgsql_* dù đồng bộ vẫn chạy — đừng dùng bảng đó để giám sát sức khoẻ sync PostgreSQL.

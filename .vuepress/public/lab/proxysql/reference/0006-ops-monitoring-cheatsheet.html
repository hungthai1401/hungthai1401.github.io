Vận hành ProxySQL — monitor + đổi config an toàn

4 lớp config đầy đủ (đính chính Reference 0003)

Ở Reference 0003 tôi nói 3 lớp — thực ra chính thức là 4, thêm 1 lớp chỉ dùng lúc khởi động lần đầu:

LớpLà gìGhi/đọc
RUNTIMECấu trúc dữ liệu thật mà worker thread đang dùngChỉ đổi qua LOAD ... TO RUNTIME
MEMORY (main)SQLite trong RAM, nơi bạn INSERT/UPDATE/DELETE bằng SQLĐọc/ghi trực tiếp qua Admin — không persist, mất khi restart nếu chưa SAVE
DISKSQLite trên disk (proxysql.db) — trạng thái "known good" sống sót qua restartChỉ đổi qua SAVE ... TO DISK
CONFIG FILEproxysql.cnf — chỉ dùng để bootstrap lần đầu (--initial)Sửa file text, không dùng để đổi config hàng ngày

Rollback "miễn phí" bạn có sẵn

Vì DISK luôn là bản "known good" cuối cùng bạn chủ động lưu, bạn có 2 đường rollback không cần backup thủ công:

  • Đã LOAD TO RUNTIME nhưng CHƯA SAVE TO DISK, thấy sai → chạy LOAD <MODULE> FROM DISK để nạp lại bản cũ vào MEMORY, rồi LOAD ... TO RUNTIME lại — hoặc đơn giản nhất: restart ProxySQL, nó tự nạp từ DISK.
  • Đã SAVE TO DISK rồi mới phát hiện sai → không còn rollback tự động; đây là lý do luôn nên có backup file proxysql.db trước khi làm thay đổi lớn (xem "Checklist đổi config" dưới).

Quy tắc productionKhông bao giờ SAVE ... TO DISK ngay sau LOAD ... TO RUNTIME. Luôn có một khoảng quan sát ở giữa (query traffic thật, check stats_mysql_connection_pool) — SAVE TO DISK chỉ khi chắc chắn runtime đang ổn.

Checklist đổi config production

  1. Backup proxysql.db (hoặc SAVE <MODULE> TO DISK hiện tại trước khi sửa, nếu muốn versioned rollback ở SQL level)
  2. Sửa ở MEMORY layer bằng SQL
  3. LOAD ... TO RUNTIME
  4. Quan sát traffic thật vài phút: stats_mysql_connection_pool, stats_mysql_query_digest, error log
  5. Ổn thì SAVE ... TO DISK. Không ổn thì LOAD ... FROM DISK rồi LOAD ... TO RUNTIME lại (hoặc restart)

Bảng stats cần theo dõi thường xuyên

BảngCho biết gì
stats_mysql_connection_poolConnection/traffic theo từng hostgroup — phát hiện hostgroup nào quá tải, node nào lỗi (ConnERR cao)
stats_mysql_query_digestQuery nào chạy nhiều/chậm, hostgroup nào nhận — phát hiện query rule route sai
stats_mysql_commands_countersPhân bố loại lệnh (SELECT/INSERT/UPDATE...) và thời gian thực thi
monitor.mysql_server_ping_logBackend còn phản hồi ping không
monitor.mysql_server_read_only_logLịch sử đọc read_only — phát hiện flapping writer/reader
stats_proxysql_servers_checksums(nếu dùng ProxySQL Cluster) node nào lệch config

Bật Prometheus exporter (built-in từ ProxySQL 2.x)

SET admin-restapi_enabled='true';
LOAD ADMIN VARIABLES TO RUNTIME;
-- endpoint mặc định: http://<proxysql-host>:6070/metrics
-- Nếu chạy nhiều ProxySQL trên cùng host, mỗi node cần admin-restapi_port khác nhau

Lưu ýKhông nên đặt scrape_interval Prometheus dưới 1 giây — metrics được tính "on-demand" mỗi lần scrape, scrape quá dày không giúp gì mà chỉ tốn tài nguyên.

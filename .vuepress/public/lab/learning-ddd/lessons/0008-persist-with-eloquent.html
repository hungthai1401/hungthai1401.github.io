Một refinement nhỏ trước khi persist: tạo mới vs khôi phục

Ở bài 7, Booking luôn được tạo với BookingId::generate() và trạng thái Held. Nhưng khi đọc từ database, bạn cần dựng lại đúng BookingId đã lưu, và đúng trạng thái đã lưu (có thể là Confirmed, không phải luôn Held). Đây là hai việc khác nhau - DDD gọi việc thứ hai là reconstitution (khôi phục), phân biệt với creation (tạo mới). 

// app/Domain/Scheduling/Models/BookingStatus.php - đổi thành backed enum
enum BookingStatus: string
{
    case Held = 'held';
    case Confirmed = 'confirmed';
    case Cancelled = 'cancelled';
}
// app/Domain/Scheduling/Models/Booking.php - thêm 2 named constructor
final class Booking
{
    private function __construct(
        private readonly BookingId $id,
        private readonly TimeSlot $timeSlot,
        private BookingStatus $status,
    ) {}

    // creation: dùng khi tạo booking mới
    public static function hold(TimeSlot $timeSlot): self
    {
        return new self(BookingId::generate(), $timeSlot, BookingStatus::Held);
    }

    // reconstitution: dùng khi đọc từ database, giữ đúng id + status đã lưu
    public static function reconstitute(BookingId $id, TimeSlot $timeSlot, BookingStatus $status): self
    {
        return new self($id, $timeSlot, $status);
    }

    public function confirm(): void { $this->status = BookingStatus::Confirmed; }
    public function cancel(): void { $this->status = BookingStatus::Cancelled; }
    public function id(): BookingId { return $this->id; }
    public function timeSlot(): TimeSlot { return $this->timeSlot; }
    public function status(): BookingStatus { return $this->status; }
}

Cập nhật RoomSchedule::reserve() ở bài 7 để gọi Booking::hold() thay vì new Booking(...), và thêm factory fromRows(): 

// app/Domain/Scheduling/Models/RoomSchedule.php
public function reserve(TimeSlot $slot): Booking
{
    // ... check overlap như bài 7 ...
    $booking = Booking::hold($slot); // thay vì new Booking(...)
    $this->bookings[] = $booking;
    return $booking;
}

/** @param array<object{id:string,start_time:DateTimeImmutable,end_time:DateTimeImmutable,status:string}> $rows */
public static function fromRows(RoomId $roomId, iterable $rows): self
{
    $schedule = new self($roomId);

    foreach ($rows as $row) {
        $schedule->bookings[] = Booking::reconstitute(
            BookingId::from($row->id),
            new TimeSlot($row->start_time, $row->end_time),
            BookingStatus::from($row->status),
        );
    }

    return $schedule;
}

Bước 3 - Repository implementation

// app/Infrastructure/Scheduling/EloquentRoomScheduleRepository.php
final class EloquentRoomScheduleRepository implements RoomScheduleRepository
{
    public function find(RoomId $roomId): RoomSchedule
    {
        $rows = BookingModel::where('room_id', $roomId->value)->get()
            ->map(fn (BookingModel $m) => (object) [
                'id' => $m->id,
                'start_time' => DateTimeImmutable::createFromInterface($m->start_time),
                'end_time' => DateTimeImmutable::createFromInterface($m->end_time),
                'status' => $m->status,
            ]);

        return RoomSchedule::fromRows($roomId, $rows);
    }

    public function save(RoomSchedule $schedule): void
    {
        foreach ($schedule->bookings() as $booking) {
            BookingModel::updateOrCreate(
                ['id' => $booking->id()->value],
                [
                    'room_id' => $schedule->roomId()->value,
                    'start_time' => $booking->timeSlot()->start,
                    'end_time' => $booking->timeSlot()->end,
                    'status' => $booking->status()->value,
                ]
            );
        }
    }
}
Gotcha đáng nhớ: Carbon vs DateTimeImmutable
Eloquent cast 'datetime' trả về Carbon, không phải DateTimeImmutable mà TimeSlot (Domain, bài 2) yêu cầu. DateTimeImmutable::createFromInterface() chuyển đổi ở Infrastructure - Domain không cần biết Carbon tồn tại. Đây chính là "hướng phụ thuộc một chiều" của bài 6, áp dụng vào một chi tiết cụ thể.

// app/Providers/AppServiceProvider.php

Bước 5 - Feature test: kiểm tra end-to-end qua DB thật

use Illuminate\Foundation\Testing\RefreshDatabase;

uses(RefreshDatabase::class);

it('không cho phép đặt trùng giờ khi đi qua repository thật', function () {
    $repository = new EloquentRoomScheduleRepository();
    $roomId = RoomId::from('room-1');

    $schedule = $repository->find($roomId); // rỗng lần đầu
    $schedule->reserve(slot('09:00', '10:00'));
    $repository->save($schedule);

    $reloaded = $repository->find($roomId);

    expect(fn () => $reloaded->reserve(slot('09:30', '10:30')))
        ->toThrow(SlotAlreadyBooked::class);
});
So sánh với bài 7
Test bài 7 (Unit, không DB) kiểm tra logic nghiệp vụ - nhanh, chạy hàng trăm lần/giây. Test này (Feature, có RefreshDatabase) kiểm tra tích hợp thật - đọc/ghi DB đúng, mapping đúng. Bạn cần cả hai loại, nhưng nên có nhiều test kiểu bài 7 và ít test kiểu này (chỉ để xác nhận phần nối dây, không lặp lại toàn bộ business logic).

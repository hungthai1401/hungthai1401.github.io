Tra cứu nhanh: DDD cho Laravel booking

Reference · Tổng hợp từ bài 1-6 · In ra hoặc để mở khi code

Building blocks tactical

Khái niệmĐịnh nghĩa ngắnVí dụ trong dự án booking
Entity Nhận diện bởi identity (ID), theo dõi qua thời gian, mutable Booking (bài 2)
Value Object Nhận diện bởi giá trị thuộc tính, immutable, không có ID TimeSlot, BookingId, RoomId (bài 2)
Invariant Quy tắc nghiệp vụ phải luôn đúng, được bảo vệ ngay trong constructor/method của domain object "start phải trước end" trong TimeSlot; "không trùng giờ" trong RoomSchedule (bài 2-3)
Aggregate Cụm Entity + Value Object, có một Aggregate Root, là ranh giới nhất quán giao dịch (invariant trong ranh giới này luôn đúng ngay sau transaction) RoomSchedule (bài 3)
Repository Interface (định nghĩa ở Domain) để load/save một Aggregate, không quan tâm cơ chế lưu trữ RoomScheduleRepository (bài 6)
Reconstitution vs Creation Tạo mới (sinh ID mới) khác với khôi phục từ DB (giữ đúng ID/trạng thái đã lưu) - nên có 2 named constructor riêng Booking::hold() vs Booking::reconstitute() (bài 8)
Domain Event Object ghi lại điều gì đã xảy ra trong domain, immutable, tên ở thì quá khứ - Aggregate ghi nhận, Application layer phát đi sau khi save() thành công BookingConfirmed (bài 9)

Building blocks strategic

Khái niệmĐịnh nghĩa ngắnVí dụ trong dự án booking
Ubiquitous Language Ngôn ngữ chung giữa dev và domain expert, dùng xuyên suốt cả trong code - nhưng chỉ nhất quán trong một Bounded Context "Booking" nghĩa khác nhau ở Scheduling vs Payment (bài 4)
Bounded Context Ranh giới trong đó một mô hình domain cụ thể là đúng và nhất quán Scheduling, Payment, Notification (bài 4-5)
Core Domain Phần hệ thống là lý do khách hàng chọn sản phẩm - đầu tư DDD tactical đầy đủ Scheduling (bài 5)
Supporting Subdomain Cần thiết, đặc thù cho bạn, nhưng không phải lợi thế cạnh tranh - model mỏng, có thể dùng SDK/package Payment (bài 5)
Generic Subdomain Ai cũng cần, không đặc thù - dùng lại package có sẵn, không tự xây Notification (bài 5)

Cấu trúc thư mục Laravel (context Scheduling)

app/
├── Domain/Scheduling/
│   ├── Models/              // Entity - PHP thuần
│   ├── ValueObjects/         // Value Object - PHP thuần
│   ├── Exceptions/
│   ├── Repositories/         // interface
│   └── Actions/              // Application layer - điều phối
├── Infrastructure/Scheduling/
│   ├── Eloquent/             // Eloquent Model - chỉ lưu trữ
│   └── Eloquent...Repository.php  // implement interface ở Domain
└── Http/Controllers/         // mỏng - chỉ gọi Action

Quy tắc phụ thuộc: Infrastructure → Application → Domain. Domain không bao giờ import Eloquent/Laravel. (bài 6)

Đề xuất Bounded Context cho dự án booking

ContextLoạiĐầu tư
SchedulingCoreFull DDD tactical (Entity/VO/Aggregate/Repository)
PaymentSupportingModel mỏng + SDK cổng thanh toán ngoài
NotificationGenericLaravel Notification có sẵn, không cần domain model

"Availability" (tìm phòng trống) chưa tách context riêng - là query đọc từ Scheduling (bài 5).

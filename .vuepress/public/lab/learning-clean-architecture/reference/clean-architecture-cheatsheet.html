Clean Architecture — Cheat Sheet

Tài liệu tham chiếu nhanh · PHP / Laravel

Quy tắc vàng

Dependency Rule

Dependency chỉ chảy hướng vào trong. Vòng trong không được biết gì về vòng ngoài.

Bốn vòng (từ trong ra ngoài)

VòngVai tròVí dụ PHP/LaravelPhụ thuộc vào
Entities Business rules cốt lõi của doanh nghiệp. Tồn tại độc lập với ứng dụng. Order, Money, Customer (thuần PHP class) Không gì cả. Không framework, không DB.
Use Cases Application business rules. Điều phối flow của một tác vụ cụ thể. CreateOrderUseCase, CancelOrderUseCase Entity + Interface (Port) của vòng ngoài
Interface Adapters Chuyển đổi dữ liệu giữa Use Cases và cấu trúc bên ngoài. Controllers, DTOs, View Models, Repository interfaces Use Case + Entity
Frameworks & Drivers Công cụ, I/O, framework. Chi tiết kỹ thuật. Laravel Router, Eloquent, MySQL, Redis, Mail, Queue Tất cả các vòng trong

So sánh nhanh: Layered vs Clean

 Layered (truyền thống)Clean Architecture
Hướng dependency Từ trên xuống dưới (UI → Logic → Data) Từ ngoài vào trong (Frames → Adapters → Use Cases → Entities)
Business logic biết về DB? Có (Service gọi trực tiếp Eloquent) Không (Use Case gọi interface, DB implement interface)
Test business logic Cần DB hoặc mocking nặng Mock interface, chạy trong RAM, nhanh
Đổi framework Viết lại phần lớn code Chỉ thay vòng ngoài, vòng trong không đổi
Phù hợp App đơn giản, CRUD, MVP nhanh App phức tạp, long-lived, nhiều domain rule

Glossary

Thuật ngữ cốt lõi

Entity: Đối tượng chứa business rule thuần. Không kế thừa Eloquent Model. Biết cách tự validate, tính toán, và áp dụng quy tắc nghiệp vụ.
Tránh gọi: Model, DTO

Use Case: Một tác vụ cụ thể mà hệ thống thực hiện (ví dụ: tạo đơn hàng, hủy đơn hàng). Chứa application flow, không chứa domain rule.
Tránh gọi: Service, Controller action

Port: Interface định nghĩa cách Use Case giao tiếp với thế giới bên ngoài. Định nghĩa ở vòng trong, implemented ở vòng ngoài.
Đồng nghĩa: Repository interface, Gateway

Adapter: Implementation cụ thể của một Port. Ví dụ: EloquentOrderRepository implements OrderRepository interface.
Đồng nghĩa: Repository implementation, Gateway implementation

DTO (Data Transfer Object): Cấu trúc dữ liệu đơn thuần, không có logic. Dùng để truyền dữ liệu giữa các layer.
Tránh gọi: Model, Entity

Dependency Inversion: Nguyên lý (SOLID - chữ D). Vòng trong định nghĩa interface, vòng ngoài implement. Đảo ngược hướng dependency tự nhiên.

Khi nào KHÔNG nên dùng Clean Architecture?

  • CRUD app đơn giản: nếu logic chỉ là tạo/đọc/sửa/xóa, Clean Architecture là overkill. Layered hoặc thậm chí controller-trực-tiếp đủ rồi.
  • MVP cần ship nhanh: deadline tuần sau? Viết thẳng trong controller, refactor sau.
  • Team chưa quen: Clean Architecture cần hiểu SOLID vững. Nếu team chưa sẵn sàng, nó trở thành儀式 thay vì giá trị.
  • App lifetime ngắn: prototype, hackathon, internal tool dùng vài tháng — không đáng đầu tư.
Nguyên tắc thực dụng

Clean Architecture là công cụ, không phải mục tiêu. Độ phức tạp của architecture phải tỉ lệ với độ phức tạp của bài toán.

Ở Bài 1 và 2, bạn đã thấy OrderId, Money, OrderStatus xuất hiện trong constructor của Order — thay vì string $id, float $total, string $status. Bài này giải thích tại sao, và dạy bạn tự viết những class như vậy.

Primitive Obsession: căn bệnh phổ biến nhất

Dùng string, int, float cho mọi thứ trông tiện, nhưng nó âm thầm loại bỏ mọi ý nghĩa nghiệp vụ khỏi type system:

function transfer(float $amount, string $currency, string $fromAccount, string $toAccount) {
    // Không gì ngăn bạn gọi transfer(-100, 'XYZ', $to, $from) — đảo ngược tham số
    // Không gì ngăn currency là "usd" viết thường, hay "US Dollar" đầy đủ
    // Không gì đảm bảo $amount không phải NaN hay số âm
}

PHP không báo lỗi vì string nào cũng là string. Bug chỉ lộ ra khi chạy — hoặc tệ hơn, không lộ ra và âm thầm sai dữ liệu.

Value Object là gì?

Value Object

Một object đại diện cho một giá trị, không có identity riêng. Hai Value Object bằng nhau nếu mọi thuộc tính bằng nhau — không quan tâm "là cùng một object" hay không. Nó immutable (không đổi state sau khi tạo) và tự validate ngay tại constructor.

So sánh với Entity mà bạn học ở Bài 2:

 EntityValue Object
Bằng nhau khi Cùng identity (OrderId giống nhau), dù thuộc tính khác đổi Mọi thuộc tính giống nhau
Ví dụ Order #123 vẫn là đơn hàng đó dù status đổi từ pending → shipped Money(100, 'USD') luôn bằng Money(100, 'USD') khác, mọi lúc
Mutable? Có thể đổi state qua method (cancel()) Không bao giờ — mọi "thay đổi" tạo instance mới

Ví dụ: Money — immutable, tự validate, có arithmetic

// app/Domain/Shared/Money.php
final class Money {
    private function __construct(
        private readonly int $cents,     // lưu bằng cents, tránh lỗi float
        private readonly string $currency,
    ) {}

    public static function fromCents(int $cents, string $currency): self {
        if ($cents < 0) {
            throw new InvalidArgumentException('Money cannot be negative');
        }
        if (!in_array($currency, ['USD', 'VND', 'EUR'], true)) {
            throw new InvalidArgumentException("Unsupported currency: {$currency}");
        }
        return new self($cents, $currency);  // invariant được đảm bảo TẠI ĐÂY, mãi mãi
    }

    public function add(Money $other): self {
        $this->assertSameCurrency($other);
        return new self($this->cents + $other->cents, $this->currency);  // instance MỚI, không đổi $this
    }

    public function equals(Money $other): bool {
        return $this->cents === $other->cents && $this->currency === $other->currency;
    }

    private function assertSameCurrency(Money $other): void {
        if ($this->currency !== $other->currency) {
            throw new CurrencyMismatchException($this->currency, $other->currency);
        }
    }

    public function toCents(): int { return $this->cents; }
    public function currency(): string { return $this->currency; }
}
Điều KHÔNG THỂ xảy ra nữa

Không có Money âm nào tồn tại trong hệ thống — constructor chặn ngay từ đầu. Không có phép cộng USD + VND vô tình xảy ra — add() tự chặn. Bug mà trước đây phải test runtime mới phát hiện, giờ không thể compile được logic sai (hoặc bị exception ngay lập tức, không lan ra xa).

Value Object làm Entity chặt chẽ hơn (nối lại Bài 2)

// So sánh: Entity dùng primitive vs dùng Value Object

// Trước — primitive obsession
final class Order {
    public function __construct(
        private string $id,
        private float $total,      // đơn vị gì? USD? cents?
        private string $status,    // giá trị hợp lệ nào? không ai biết trừ khi đọc code khác
    ) {}
}

// Sau — Value Objects làm rõ ý nghĩa và tự bảo vệ invariant
final class Order {
    public function __construct(
        private OrderId $id,           // không thể nhầm với CustomerId (cũng là string)
        private Money $total,          // luôn có currency, luôn >= 0
        private OrderStatus $status,   // enum, chỉ nhận giá trị hợp lệ
    ) {}
}

Kiểm tra hiểu biết

Money::fromCents(100, 'USD') và Money::fromCents(100, 'USD') — hai instance khác nhau trong bộ nhớ. Chúng có "bằng nhau" theo nghĩa Value Object không?

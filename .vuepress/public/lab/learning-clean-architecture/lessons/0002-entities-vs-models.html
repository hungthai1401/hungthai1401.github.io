Entities vs Eloquent Models

Bài 2 / Clean Architecture + Laravel · ~10 phút

Bài 1 nói: Entity không được biết gì về vòng ngoài. Nhưng trong Laravel, mọi model bạn viết đều kế thừa Illuminate\Database\Eloquent\Model. Vậy cái class Order mà bạn extends Model — nó là Entity hay là gì khác?

Câu trả lời: nó không phải Entity. Nó là Active Record. Hai thứ này trông giống nhau nhưng giải quyết vấn đề khác nhau, và trộn chúng lại là lý do phổ biến nhất khiến người ta "làm Clean Architecture" nhưng vẫn bị kẹt Eloquent trong business logic.

Active Record vs Entity

Active Record (Eloquent Model)

Một object vừa giữ dữ liệu vừa biết cách tự lưu/xóa/query chính nó vào database. $order->save() hoạt động vì Order biết về table, connection, query builder.

Entity (Domain Object)

Một object chỉ giữ dữ liệu và business rule. Nó không biết database tồn tại. $order->cancel() chỉ thay đổi state trong bộ nhớ và áp dụng quy tắc nghiệp vụ — không có câu SQL nào chạy.

Vấn đề của Active Record không phải nó "xấu" — nó rất tiện cho CRUD. Vấn đề là nó trộn hai trách nhiệm: persistence (lưu trữ) và business rule (nghiệp vụ). Theo Dependency Rule ở Bài 1, hai thứ này phải nằm ở hai vòng khác nhau.

Ví dụ: quy tắc nghiệp vụ ở đâu?

Giả sử: "Đơn hàng chỉ được hủy khi chưa giao (status ≠ shipped) và trong vòng 24h kể từ lúc tạo." Đây là business rule. Nó thuộc vòng Entity — không phụ thuộc Laravel, không phụ thuộc DB.

Cách thường gặp: rule nằm trong Eloquent Model

class Order extends Model {
    public function cancel(): void {
        if ($this->status === 'shipped') {
            throw new Exception('Cannot cancel shipped order');
        }
        if ($this->created_at->diffInHours(now()) > 24) {
            throw new Exception('Cancellation window expired');
        }
        $this->status = 'cancelled';
        $this->save();  // ← business rule và persistence dính chặt vào nhau
    }
}
Tại sao đây là vấn đề?

Để test rule "24h" và "chưa shipped", bạn phải có một database thật, chạy migration, insert record. Business rule — thứ đáng lẽ test được trong vài milli-giây — giờ chậm và giòn (fragile) vì phụ thuộc I/O.

Clean Architecture: Entity thuần, Eloquent chỉ là cái vỏ lưu trữ

// Vòng TRONG: app/Domain/Order/Order.php — thuần PHP, không "extends" gì cả
final class Order {
    public function __construct(
        private OrderId $id,
        private OrderStatus $status,
        private DateTimeImmutable $createdAt,
    ) {}

    public function cancel(DateTimeImmutable $now): void {
        if ($this->status->isShipped()) {
            throw new CannotCancelShippedOrder();
        }
        $hours = ($now->getTimestamp() - $this->createdAt->getTimestamp()) / 3600;
        if ($hours > 24) {
            throw new CancellationWindowExpired();
        }
        $this->status = OrderStatus::cancelled();  // chỉ đổi state trong RAM
    }

    public function status(): OrderStatus { return $this->status; }
}
// Vòng NGOÀI: app/Infrastructure/Persistence/Models/OrderModel.php — Eloquent thuần túy, không có business rule
class OrderModel extends Model {
    protected $table = 'orders';
    protected $fillable = ['status', 'created_at'];
    // Không method nghiệp vụ nào ở đây. Chỉ là cái vỏ lưu trữ.
}
// Adapter nối hai bên: chuyển đổi Entity ↔ Eloquent Model
class EloquentOrderRepository implements OrderRepository {
    public function find(OrderId $id): Order {
        $row = OrderModel::findOrFail($id->value());
        return new Order(
            new OrderId($row->id),
            OrderStatus::from($row->status),
            $row->created_at->toDateTimeImmutable(),
        );  // row → Entity
    }

    public function save(Order $order): void {
        OrderModel::updateOrCreate(
            ['id' => $order->id()->value()],
            ['status' => $order->status()->value()],
        );  // Entity → row
    }
}
Kết quả

Test Order::cancel() giờ chỉ cần: new Order(...), gọi cancel(), assert exception hoặc state mới. Không database, không Laravel bootstrap. Chạy trong <1ms.

Cái giá phải trả

Đừng ngộ nhận đây là miễn phí. Bạn giờ có hai class cho một khái niệm "Order" (Entity + Eloquent Model), và một lớp mapping ở giữa. Với app CRUD đơn giản, đây là chi phí không đáng — Eloquent Model đủ dùng. Chỉ tách khi Entity có business rule đủ phức tạp để đáng test độc lập.

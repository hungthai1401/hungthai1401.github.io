Ghép lại: dự án Laravel mới

Bài 6 / Clean Architecture + Laravel · ~12 phút · Bài tổng kết

Năm bài trước dạy từng khái niệm riêng lẻ: Dependency Rule, Entity, Use Case, Port/Adapter, Testing. Bài này ghép chúng lại thành một dự án Laravel thật, từ laravel new đến feature đầu tiên chạy được — đúng với mục tiêu ban đầu của bạn trong MISSION.md: xây dựng dự án mới đúng cách ngay từ đầu.

Bước 1: Cấu trúc thư mục — không cần sửa composer.json

Tin tốt: Laravel mặc định map namespace App\ vào thư mục app/ qua PSR-4. Nghĩa là app/Domain/Order/Order.php tự động thuộc namespace App\Domain\Order — không cần sửa gì trong composer.json. Chỉ cần tạo thư mục và đặt namespace đúng.

Lệnh khởi tạo

laravel new my-app, sau đó mkdir -p app/{Domain,Application/Ports,Infrastructure/Persistence/Models,Infrastructure/Payment}. Laravel không quan tâm bạn đặt thư mục nào miễn namespace khớp đường dẫn.

Bước 2: Nối dây — AppServiceProvider

Đây là nơi duy nhất trong toàn bộ app biết cả Port và Adapter cùng lúc. Mọi vòng khác chỉ biết một bên.

// app/Providers/AppServiceProvider.php
public function register(): void {
    $this->app->bind(OrderRepository::class, EloquentOrderRepository::class);
    $this->app->bind(PaymentGateway::class, StripePaymentGateway::class);
}

Bước 3: Route → Controller → Use Case

// routes/api.php
Route::post('/orders', [OrderController::class, 'store']);

Laravel tự resolve OrderController, thấy nó cần CreateOrderUseCase, thấy Use Case đó cần OrderRepository và PaymentGateway — và tự tiêm EloquentOrderRepository + StripePaymentGateway nhờ binding ở Bước 2. Bạn không phải new tay bất cứ thứ gì.

Đường đi của một request, từ đầu đến cuối

Controller đọc Request → Use Case điều phối → Entity áp dụng rule → Use Case gọi Port → Adapter thực thi persistence
